# MCP Server 安全与网络扩展任务

## 目的

当前 `c-mcp-server` 已经实现了一个基础的 MCP HTTP JSON-RPC 服务，但它只支持明文 HTTP 且没有任何鉴权。
这意味着任何知道服务地址的人都可以直接访问 `POST /mcp/api`，包括 `tools/call` 等敏感接口。

本文件用于说明后续扩展任务，帮你逐步把程序从“可用原型”改成“安全可靠”的网络服务。

## 当前程序缺陷

1. 明文传输（HTTP）
   - 请求和响应内容都以明文传输，容易被中间人窃听。
   - 不适合传输敏感数据或在不受信任网络中使用。

2. 无认证/鉴权
   - 任何客户端均可调用 MCP 接口。
   - 无法区分合法用户与恶意攻击者。

3. 输入验证不足
   - 目前只做了最简单的 JSON 解析。
   - 未对字段长度、字符串内容、参数范围、JSON schema 做充分限制。

4. 访问控制缺失
   - 不限制源 IP、客户端类型或请求速率。
   - 容易被自动化扫描、暴力请求、DDoS 攻击利用。

5. 错误信息和日志策略不完善
   - 当前只返回简单响应，日志未区分安全事件。
   - 错误内容可能无法满足审计需求。

6. 依赖/构建安全性
   - 未说明编译时应开启的安全编译选项。
   - 没有专门的安全审计或运行时防护建议。

## 扩展项列表

以下是建议优先添加的扩展内容。每一项都包含名词、说明、参数及作用。

### 1. HTTPS / TLS 支持

- 名称：`TLS/HTTPS`
- 说明：用加密通道保护客户端和服务器之间的通信，防止窃听和中间人篡改。
- 参数：
  - `server_cert_path`：服务器证书文件路径
  - `server_key_path`：服务器私钥文件路径
  - `tls_port`：TLS 监听端口（例如 8443）
- 作用：
  - 加密传输内容
  - 校验证书合法性
  - 保证数据在传输过程中的机密性和完整性

### 2. 认证机制

- 名称：`API Key / Token 验证`
- 说明：为每个客户端分配访问凭证，只有持有有效凭证者才能调用接口。
- 参数：
  - `auth_type`：例如 `api_key`、`bearer_token`
  - `auth_header`：验证头名，如 `Authorization`
  - `api_key_list`：允许访问的 API Key 列表
  - `token_expiry`：令牌过期时间
- 作用：
  - 防止未授权访问
  - 提供访问控制基础
  - 可在未来扩展为用户角色/权限管理

### 3. 权限控制与接口白名单

- 名称：`接口授权和权限分离`
- 说明：不同客户端只允许调用允许的接口，不同操作需要不同权限。
- 参数：
  - `role`：客户端角色，如 `reader`、`caller`、`admin`
  - `allowed_methods`：该角色可调用的 MCP method 列表
- 作用：
  - 限制敏感操作
  - 防止低权限客户端做高权限调用

### 4. 请求参数校验

- 名称：`严格参数验证`
- 说明：对每个 API 请求进行结构和内容校验，拒绝非法或超长输入。
- 参数：
  - `max_body_size`：最大请求体大小
  - `max_string_length`：允许的最大字符串长度
  - `supported_content_type`：仅接受 `application/json`
  - `input_schema`：工具级输入 schema
- 作用：
  - 减少解析异常
  - 防止内存溢出、缓冲区溢出
  - 限制恶意请求数据量

### 5. 速率限制 / 限流

- 名称：`请求速率限制`
- 说明：防止单个客户端在短时间内发起大量请求，造成资源耗尽。
- 参数：
  - `requests_per_minute`：每分钟允许请求次数
  - `burst_limit`：允许的突发请求数
  - `client_identifier`：基于 IP / API Key 的限流键
- 作用：
  - 降低暴力攻击风险
  - 防止服务被恶意压垮

### 6. IP 白名单 / 网络访问控制

- 名称：`IP 白名单`
- 说明：只允许来自可信 IP 或网段的请求访问服务。
- 参数：
  - `allowed_ips`：允许访问的 IP 列表
  - `blocked_ips`：明确拒绝的 IP 列表
- 作用：
  - 进一步保护服务入口
  - 适用于内网部署或 VPN 环境

### 7. 日志与审计

- 名称：`安全日志与审计`
- 说明：记录关键请求、认证失败、异常情况和访问者信息。
- 参数：
  - `log_level`：日志级别，例如 `info`、`warn`、`error`
  - `audit_log_path`：审计日志文件路径
  - `log_format`：日志格式，如 JSON 或文本
- 作用：
  - 帮助发现攻击行为
  - 支持故障排查和安全审计

### 8. 错误处理改进

- 名称：`安全错误返回`
- 说明：错误响应不泄露内部实现和敏感细节。
- 参数：
  - `hide_internal_errors`：是否隐藏内部错误消息
  - `error_code_mapping`：对外错误代码与内部错误类型的映射
- 作用：
  - 防止攻击者通过错误信息推测系统结构
  - 保持对外接口的一致性

### 9. 运行时安全编译选项

- 名称：`编译器安全增强`
- 说明：构建时开启防护选项，增加内存安全保底。
- 参数：
  - `-D_FORTIFY_SOURCE=2`
  - `-fstack-protector-strong`
  - `-Wl,-z,relro,-z,now`
  - `-pie`
- 作用：
  - 防止栈溢出和常见攻击
  - 提升程序整体抗攻击能力

## 具体扩展任务建议

### 任务 1：添加 HTTPS/TLS 支持

- 在 `src/http_server.c` 中引入 TLS 库（例如 OpenSSL / mbedTLS）。
- 调整监听逻辑，支持 TLS 端口。
- 在 `README.md` 或新文档中记录证书路径配置。

### 任务 2：添加身份认证层

- 在请求入口处检查 `Authorization` 头或自定义 `X-API-Key`。
- 验证请求是否携带有效凭证。
- 如果凭证无效，返回 `401 Unauthorized`。

### 任务 3：增加请求合法性检查

- 检查 `Content-Type` 必须为 `application/json`。
- 检查 `Content-Length` 合法范围。
- 对 `tools/call` `arguments` 做更严格 JSON schema 校验。

### 任务 4：添加访问控制策略

- 对 MCP 方法进行角色权限限制。
- 例如：只有 `admin` 可调用 `resources/read`，普通用户只能调用 `tools/list` 和 `tools/call`。

### 任务 5：增加限流和防护

- 在 `handle_client` 入口或请求调度前实现简单限流。
- 记录每个客户端单位时间内的请求次数。
- 超限后返回 `429 Too Many Requests`。

### 任务 6：完善日志和异常监控

- 增加服务端日志记录入口 IP、请求方法、结果状态。
- 对认证失败、无效请求、内部错误单独记录。

## 为什么要做这些扩展

1. **防止数据泄漏**：仅 HTTPS 能保证传输过程不被监听。否则用户传输的 JSON 和返回内容都可能被抓包。
2. **防止未授权访问**：没有鉴权时，任何人都可以调用内部工具，漏洞风险极高。
3. **提升稳定性**：限流与参数校验能够防止恶意请求造成崩溃或服务不可用。
4. **增强可控性**：访问控制和日志让服务行为可审计、可管理。
5. **为未来扩展打基础**：认证、权限、TLS 是后续增加更多工具和资源接口的必备前提。

## 推荐优先级

1. TLS/HTTPS
2. 认证/鉴权
3. 参数校验与错误处理
4. 速率限制 / 访问控制
5. 日志 / 审计 / 安全编译

## 结语

这个文档作为后续扩展任务的参考。按照优先级逐步实施，程序会从“简单演示服务”逐渐演进为“安全可靠的网络服务”。
